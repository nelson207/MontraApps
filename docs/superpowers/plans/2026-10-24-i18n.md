# Multilingual UI (i18n) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** English / Portuguese UI for all Montra apps, chosen by the user; phase 1 = setup + pilot screens.

**Architecture:** `i18next` initialised in `platform/i18n` with `en` bundled and `pt-PT` loaded on
demand; `languageSlice.choice` (persisted in the preferences) + `uiCulture` from `/api/users/me`
→ `resolveLanguage` → `useApplyLanguage` (in App) changes i18next's language, `<html lang>`;
`emptyApi` sends `Accept-Language`. Components use `useTranslation(ns)`.

**Tech Stack:** React 19, Redux Toolkit, i18next, react-i18next, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-24-i18n-design.md`

## Global Constraints

- `en` is the default and fallback; stored values other than `en | pt-PT` are ignored.
- Keys are typed from the `en` resources (`platform/i18n/i18next.d.ts`); `pt-PT` must have every `en` key (test).
- Text from the API is never translated in the client.
- The app namespace comes through the `@app/i18n` contract (APP_MESSAGES), like the other app files.

## Tasks

1. Dependencies (`i18next`, `react-i18next`); `platform/i18n`: languages, resolution, init, lazy `pt-PT`, typing.
2. `languageSlice` (choice, persisted) + `useApplyLanguage` (choice → uiCulture → en, `<html lang>`).
3. `Accept-Language` on every request (`emptyApi.prepareHeaders`).
4. Language picker: Settings → Appearance and the user menu.
5. `problemMessage` → `errors` namespace.
6. Pilot screens: login flow, layout (sidebar module labels via the app namespace, top bar, user
   menu, notifications menu), Settings page and Appearance.
7. Tests: resolution, header, locale key parity, a component switching language; lint, tests, five builds.

## Review Focus

- First paint in English (no flash of keys); switching to Portuguese loads it once and re-renders without reload.
- A user with `uiCulture` `pt-PT` and no choice sees Portuguese after signing in; choosing English sticks.
- Login page (before sign-in) honours the stored choice.
- Error messages from codes are translated; a code without a key falls back to the generic text.
