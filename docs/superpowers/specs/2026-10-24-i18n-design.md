# Multilingual UI (i18n) — design spec

Date: 2026-10-24 · Status: approved design

## Goal

Every Montra app (Credit, Lawyer, Stock, Factoring, Customer) in English and Portuguese, chosen
by the user, without a reload. Text coming from the API (business names, products, countries…)
stays as the API sends it until the backend translates it.

## Decisions

| Topic | Decision |
|---|---|
| Library | `i18next` + `react-i18next` (`useTranslation`, `t`, `<Trans>`) |
| Languages | `en` (default and fallback), `pt-PT` |
| Which language | 1) the user's choice (this browser) → 2) `uiCulture` from `GET /api/users/me` (`pt*` → `pt-PT`, `en*` → `en`) → 3) `en`. The browser language is not used |
| Changing it | Settings → Appearance → Language, and the user menu. Stored in the preferences (`language`) — the API has no endpoint for users to save their own `uiCulture` yet |
| Keys | Typed: `en` resources are the source of truth; a TypeScript declaration makes `t("…")` keys checked by `tsc` |
| Namespaces | `common` (shared words: Save, Cancel, Retry…), one per platform feature (`auth`, `layout`, `settings`…), one per app (`credit`, `stock`…) |
| Files | `platform/i18n/locales/<lang>/<ns>.json`; `apps/<app>/i18n/locales/<lang>.json` for the app namespace |
| Loading | `en` bundled; `pt-PT` loaded lazily (dynamic import) when chosen |
| Errors | `problemMessage` maps ProblemDetails codes to keys (`errors:<code>`) |
| Dates / numbers / money | `Intl` with the active language; the date *format* stays the Appearance setting |
| API | Every request sends `Accept-Language` with the active language, so the backend can translate later |
| `<html lang>` | Follows the language |
| Module labels | `AppModule.label` becomes a key (`layout:modules.<id>`) |

## Scope

Phase 1 (this change): setup, language choice (Settings + user menu), `Accept-Language`,
`<html lang>`, error messages, and the pilot screens translated end to end: login (password,
2FA, forgot password, change required), layout (sidebar, top bar, user menu, notifications menu),
Settings page and Appearance.
Next phases, one feature at a time: account/profile, users, news, tasks, results views,
work context, then each app's screens.

## Testing

Vitest: language resolution (choice → uiCulture → en), `uiCulture` mapping, `Accept-Language`
header, a component test switching language. Every `en` key exists in `pt-PT` (test).
`npm run lint`, `npm test`, all five builds.
